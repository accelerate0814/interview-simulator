# 三方向共同 SPEC — 面试模拟练习 · 前端全站重设计初稿

## 产品是什么
「面试模拟练习」——一个人独自练面试的 Web 工具。选岗位和级别，AI 面试官逐题发问、当场点评，结束后给一份带参考答案和评分的复盘。用户在练习时本就紧张，界面要么帮他降压、要么让他觉得「这是玩真的值得认真」——不要幼稚、不要考试系统的冷硬。中文界面。

当前线上版是「暖调教练风」（赤陶橙 + Newsreader 衬线 + 米白纸底），用户觉得还能再改，想看不同方向。**不要再做这一版**（它正好是 AI 套路里的「Warm Editorial」）。

## 一个 HTML 里要画全这 5 块（纵向堆叠，每块上方一个小 caption 标注是哪一屏）
1. **侧栏**（常驻左栏）：logo「面试模拟」+「新的一场」按钮；分组「历史记录」（2 条示例）/「面试中可用」（7 个指令按钮）/「这场面试」（用时 + 已答 读数）；底部 5 个工具入口
2. **欢迎首屏**（会话未开始）：overline + 大标题 + 一段正文 + 主 CTA + 一行能力点
3. **面试进行中**：面试官发言 + 你的作答（至少各 2 条）+ 底部输入区（文本框 + 麦克风 + 发送 + 快捷键提示）
4. **复盘浮层**：头部标题 + 下载/关闭；meta 行（岗位/层级/综合评分/结论）；「逐题回顾」1 张题卡（题干 + 分 + 你的回答 + 参考答案 + 点评）；「总体评价」3 卡
5. **设置类浮层**：模型配置（服务商 chip + API Key / Base URL / 模型名称 + 保存/恢复默认）

## 真实文案（用这些，不要 Lorem / 不要编数字）
- logo `面试模拟` · 按钮 `新的一场`
- 侧栏分组 `历史记录` / `面试中可用` / `这场面试`
- 历史 2 条：`后端开发工程师 · 面这个岗位练一下`（刚刚 · 3 轮）、`数据分析师`（2 小时前 · 8 轮）
- 指令按钮：`要一个提示` `跳过这题` `看参考答案` `看当前评分` `加大难度` `降低难度` `结束面试`
- 读数：`用时 12:34` / `已答 5`
- 底部工具：`语音播报` `深色模式` `我的资料` `我的题库` `模型配置`
- 欢迎 overline：`练习，然后再上场`
- 欢迎大标题：`把面试当练习，一题一题过。`
- 欢迎正文：`选好岗位和级别，面试官逐题发问、当场点评；结束后给你一份带参考答案和评分的完整复盘。`
- 欢迎 CTA：`开始面试`
- 欢迎能力点：`语音或打字作答 · 逐题评分 · 随时要提示或跳过 · 结束出复盘`
- 聊天示例：
  - 面试官：`我们先从系统设计聊起。为一个日活百万的应用设计短链接服务的存储层，说说你的取舍。`
  - 你：`先用关系型数据库存 长链→短码 的映射，短码用发号器生成，再加一层缓存扛读。写入量不大，读多写少。`
  - 面试官：`那发号器怎么保证高可用？如果它挂了，整个写入链路就断了。有没有备选方案？`
- 输入占位：`写下你的回答，或点麦克风口述` · 提示：`Enter 发送 · Shift + Enter 换行`
- 复盘：标题 `面试复盘` · 按钮 `下载 Word` `关闭`
- 复盘 meta：`岗位 后端开发工程师` / `层级 中级 · P6` / `综合评分 6.5/10` / `结论 Lean Hire`
- 复盘小标题：`逐题回顾` / `总体评价`
- 题卡：`Q1` · `为一个日活百万的应用设计短链接服务的存储层，说说取舍。` · `7/10`
  - `你的回答`：`用关系型数据库存映射，短码用发号器生成，加缓存扛读。读多写少。`
  - `参考答案`：`关键点：短码生成策略（发号器 / hash / 预生成池）、存储选型与容量估算、缓存与热点、301 vs 302、防刷与过期。能主动给出 QPS 与存储量的量级估算是加分项。`
  - `点评`：`方向对，但没做容量估算，也没提发号器的高可用；追问后才补上。`
- 总体评价 3 卡：`做得好的`（基础结构清晰，能快速给出可行方案 / 愿意在追问下修正）、`可以更好的`（缺少量级估算的习惯 / 高可用、容灾常被漏掉）、`建议补的`（容量估算：QPS / 存储 / 带宽的口算 / 分布式发号器：Snowflake、号段模式）
- 设置：标题 `模型配置` · `选择服务商` chip：`DeepSeek 千问 智谱 OpenAI Moonshot OpenRouter` · 字段 `API Key` `Base URL` `模型名称` · 按钮 `保存` `恢复默认` · 状态 `已保存`

## 硬约束（任何风格都不豁免）
- 单文件 HTML，内联所有 CSS，可 `file://` 双击打开。Google Fonts 用 `<link>` 引可以。
- 正文 ≥14px、标签/注释 ≥12px、正文对比度 ≥4.5:1。留白必须是构图（首屏有明确视觉锚点），不是内容缺席。
- **不用 emoji 当图标**——图标用内联线性 SVG（1.5–2px 描边）或纯 CSS 形状。
- 不编造统计/testimonial/logo 墙。
- 颜色走「采样→收敛→论证」：2–3 个有彩色 + 1 组中性明度序列，用 `oklch()` 或 hex 皆可，HTML 顶部注释写一句「主色为什么是这个色」。
- 字体：display + body 配对，用开源字（Fraunces/Newsreader/Space Grotesk/Archivo/Manrope/IBM Plex/Geist/Instrument Serif 等），标题一律 roman（不用斜体标题）。**不要用 Newsreader 衬线 + 赤陶橙**（撞现版）。
- 视口按 1440 宽设计；侧栏 + 主区左右布局；聊天/复盘正文阅读宽度 ≤ 70ch。
- 深色模式不强制，做了是加分。
- HTML 顶部注释写一句：**form（版式）来自内容的哪里**（面试的什么特质长出了这个结构）。

## 母题种子（各版自选一个，别都一样）
面试 = 「一问一答的回合」+「结束后被记录、被打分」。候选视觉母题：录音棚 / 回放带子、靶场 / 命中环、关卡 / 进阶、问答手稿 / 卷宗、排练厅 / 上场、仪表盘 / 读数。
